= Message delivery

== Lifecycle

. The API validates the request, builds a message, and queues it. The message is `queued`,
  and its status can be polled from now on.
. A delivery worker takes the message and sends it to the SMSC as one `submit_sm` per part.
  Text that fits one SMS is one part.
. When the SMSC accepts every part, the message becomes `sent`, and {product} records the
  SMSC's message id for each part, for receipt correlation.
. If the send fails, the message waits `delivery.retry_delay` seconds and is queued again.
  After `delivery.max_retries` attempts in total it ends `failed`.
. Some failures are permanent: text needing more than 255 parts ends `failed` at once, with
  no retry.

. A delivery receipt from the SMSC then moves a `sent` message to `delivered`, `failed` or
  `expired`. See <<Delivery receipts>>.

A message becomes `delivered`, or `expired`, only from a delivery receipt.

== Encoding and length

{product} picks the SMPP `data_coding` for each message:

* **GSM 03.38 (`data_coding` 0)** when every character is in the GSM 7-bit alphabet or its
  extension table. One SMS holds 160 septets, and extension characters such as `€`, `[`,
  `]`, `{`, `}`, `~` and the backslash take two.
* **UCS-2 (`data_coding` 8)** otherwise. One SMS holds 70 characters, and a character outside
  the Basic Multilingual Plane, such as most emoji, takes two.

Longer text is sent as a concatenated SMS: several parts, each carrying a user data header
(UDH) that lets the handset reassemble them. The header takes room, so each part holds 153
GSM or 67 UCS-2 characters. An extension character is never split across two parts. A
message can have at most 255 parts.

== Addresses

{product} sets the SMPP type of number (TON) and numbering plan (NPI) from each address:

* `+` followed by digits goes out as international/ISDN, without the `+`.
* Plain digits go out as unknown/unknown.
* Anything else, such as `Porth`, goes out as an alphanumeric sender.

Spaces and `-` in numbers are ignored.

== The SMSC bind

{product} opens one transceiver bind to the configured SMSC.

* If the bind fails at startup, the gateway still starts and retries the bind every 10 s.
* A bind that is lost, or that the SMSC unbinds, is reopened within 10 s, even when nothing
  is being sent.
* When a send fails at the transport level (timeout, lost connection, not bound), {product}
  drops the bind. The next send, or the 10 s retry, opens a new one.
* An error *response* from the SMSC, such as an invalid destination or throttling, keeps the
  bind open. That message goes through the normal retry path.
* A send that times out is retried, even though the SMSC may already have accepted it. The
  recipient can then get the message twice.
* If one part of a long message fails, the whole message is retried, with every part sent
  again. The recipient may also see an incomplete fragment from the failed attempt.

== Delivery receipts

{product} asks the SMSC for a receipt (`registered_delivery = 1`) for every message. Each
receipt reports on one part, by the SMSC message id the SMSC returned for it, and moves the
message on as follows:

[cols="2,3",options="header"]
|===
| Receipt state | Message status

| `DELIVERED` | `delivered`, once every part has a `DELIVERED` receipt
| `UNDELIVERABLE`, `REJECTED`, `DELETED` | `failed`, on the first such part
| `EXPIRED` | `expired`, on the first such part
| `ENROUTE`, `ACCEPTED`, `UNKNOWN`, or none | unchanged, not a final outcome
|===

`delivered_at` is the time the last part's receipt arrived, in UTC. HTTP API clients see
the new status on their next poll. For a Kannel `dlr-url` callback, see <<Delivery reports>>.

* A receipt is matched by the exact SMSC message id. A receipt whose id {product} does not
  know yet is looked up again for about 15 s, so a part's receipt that arrives before the
  later parts are submitted still counts. After that, it is logged at info and ignored. If
  every receipt is ignored, the SMSC reports ids in a different format from its `submit_sm`
  responses.
* A receipt for a message that is already `delivered`, `failed` or `expired` is ignored.
* Receipts arrive only while the bind is up. After a lost bind, the receipts the SMSC holds
  arrive once {product} rebinds, within 10 s.
* Receipts already received when {product} closes a bind are still applied.
* Other inbound messages (mobile-originated SMS) are acknowledged and dropped.
