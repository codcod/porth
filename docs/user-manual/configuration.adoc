= Configuration

{product} reads all of its configuration from one TOML file, the `[porth]` table and its
sub-tables. The file's path is the command's argument, `config/config.toml` by default:

[source,bash]
----
bin/porth /etc/porth/config.toml
----

`make run` uses the repository's `config/config.toml`, which holds development values. Other
top-level tables in the file are ignored.

There are no environment-variable overrides and no `.env` file. Secrets such as the SMSC
password, the Kannel users' passwords, the HTTP users' tokens and the database DSN live in the file, so a production
deployment mounts its own `config.toml`, as a secret, and passes its path.

== Validation

{product} checks the file at startup and stops with an error naming the key when:

* a key is unknown, such as `porth.http.hostname`;
* a value has the wrong type. Values are never converted: `port = "8080"` is an error, as is
  `reply = "yes"` or an unquoted `default_sender = 12345`;
* a required key is missing, such as `porth.smsc.op-a.host`;
* a routing rule is not digits, or names an SMSC that is not configured;
* a Kannel or HTTP user's `allow_ip` entry is not an address or CIDR network, or has host bits
  set (`10.0.0.1/8`), such as `invalid porth.kannel.users.acme.allow_ip: '10.0.0.1/8'`;
* an HTTP user's `token` is shorter than 16 characters
  (`invalid porth.http.users.app.token: shorter than 16 characters`), or is the same as another
  user's (`invalid porth.http.users.b.token: the same as porth.http.users.a.token`);
* `log_level` is not a Python logging level name (`DEBUG`, `INFO`, `WARNING`, `ERROR`,
  `CRITICAL`);
* `log_format` is neither `text` nor `json` (`invalid porth.log_format: 'xml'`);
* `http.callback_retry_minutes` is below 1
  (`invalid porth.http.callback_retry_minutes: must be at least 1`);
* an SMSC's `tls_ca_file` is set without `tls = true`
  (`invalid porth.smsc.op-a.tls_ca_file: set tls = true to use it`), or can't be read as PEM
  CA certificates (`invalid porth.smsc.op-a.tls_ca_file: [Errno 2] No such file or
  directory`); `make config-check` catches both;
* the file has no `[porth]` table.

`make config-check` (`bin/porth --check <file>`) runs the same checks on
`config/config.toml` without connecting to anything.

{product}, and `make config-check`, also refuse an in-memory SQLite `db`
(`sqlite+aiosqlite:///:memory:`): `db: an in-memory SQLite database is not supported; use a
file`.

== Settings

Keys are given relative to `[porth]`: `http.port` is `port` in `[porth.http]`.

[cols="2,1,4",options="header"]
|===
| Setting | Default | Meaning

| `http.host` | `0.0.0.0` | Address the HTTP API listens on.
| `http.port` | `8080` | Port the HTTP API listens on.
| `http.users.<name>` | none | One `/api/v1` caller per table. See <<HTTP users>>.
| `http.callback_retry_minutes` | `5` | How long a REST status callback is retried, in minutes.
  Waits double from 2 s, at most 300 s each, and a new attempt is made while the waits fit
  the window: the default gives 8 attempts over about 4 minutes. The last attempt can come up
  to 300 s before the window ends, so set it about 5 minutes above the longest receiver
  outage to cover (65 for an hour). A restart starts the window again. A Kannel `dlr-url`
  keeps its 3 attempts.
| `kannel.host` | `0.0.0.0` | Address the Kannel-compatible API listens on.
| `kannel.port` | `13013` | Port the Kannel-compatible API listens on.
| `kannel.default_sender` | none | Sender for a `sendsms` request without `from`, like Kannel's
`global-sender`. A string: quote a numeric short code.
| `kannel.users.<username>` | none | One `sendsms` caller per table. See <<Kannel users>>.
Without any, `sendsms` is open.
| `smsc.<name>` | none | One upstream SMSC per table, named by the table's key. See
<<SMSCs>>. Without any, nothing routes and every submit is refused.
| `routing.default` | unset | The SMSC for a number no prefix matches. See <<Routing rules>>.
| `routing.prefixes` | empty | Destination prefix to SMSC name. See <<Routing rules>>.
| `delivery.max_retries` | `3` | Total delivery attempts per message, including the first.
| `delivery.retry_delay` | `5` | Seconds before the first retry.
| `delivery.backoff_factor` | `2` | Each later retry waits this many times longer. `1` keeps
every wait at `delivery.retry_delay`.
| `delivery.max_retry_delay` | `300` | Longest wait before a retry, in seconds.
| `delivery.worker_count` | `10` | Concurrent delivery workers, for each SMSC: two SMSCs
have ten each.
| `mo.url` | unset | The application URL each MO is fetched from, with Kannel escape codes.
Unset: MO is logged and dropped. See <<Mobile-originated messages>>.
| `mo.reply` | `true` | Send the application's `text/plain` answer back as an SMS.
| `store.dlr_timeout_hours` | `48` | Hours a `sent` message waits for its delivery receipt
before it becomes `expired`. At least `1`. See <<Lifecycle>>.
| `store.retention_days` | `7` | Days after it was accepted that a finished message is
deleted (later while a status call is still being made). At least `1`. See <<Lifecycle>>.
| `db` | unset | **Required.** The database, as a SQLAlchemy DSN. PostgreSQL in the asyncpg
form, `postgresql+asyncpg://USER:PASSWORD@HOST:5432/porth`, or a SQLite file in the aiosqlite
form, `sqlite+aiosqlite:////var/lib/porth/porth.db` (four slashes for an absolute path; see
<<Running on SQLite>>). The shipped `config/config.toml` points at `make db-up`'s database.
`make migrate` reads it from the same file.
| `log_level` | `INFO` | Level of the log output, in UTC.
| `log_format` | `text` | `text`: one plain line per record on standard error. `json`: one
JSON object per line, for a log shipper such as Loki, ELK or Datadog, with the keys `time`
(UTC, `2026-10-12T10:39:12.345Z`), `level`, `logger`, `message` (the text line's message),
`exc` (a traceback, when there is one), and `message_id` and `smsc` on the lines about a
message or an SMSC. The REST API's access lines add aiohttp's own fields, such as
`remote_address` and `response_status`.
|===

== SMSCs

Each `[porth.smsc.<name>]` table is one SMSC {product} binds to, by default as a
transceiver. The name
is the table's key, such as `op-a` in `[porth.smsc.op-a]`, and may not be empty. It appears
in the logs, in the routing rules, in the Kannel `smsc` parameter and as `%i`.

[cols="2,1,4",options="header"]
|===
| Key | Default | Meaning

| `host` | none | **Required.** The SMSC's address.
| `port` | `2775` | The SMSC's port.
| `system_id` | none | **Required.** The bind's system id.
| `password` | none | **Required.** The bind's password.
| `system_type` | empty | The bind's system type.
| `throughput` | unset | Most `submit_sm` PDUs this SMSC gets in any one second: the
operator's contracted rate. A concatenated message counts once per part. Unset: unlimited.
At least `1`. See <<Throughput cap>>.
| `transceiver` | `true` | `false`: for an SMSC without transceiver binds, {product} opens a
transmitter bind for `submit_sm` and a separate receiver bind for receipts and MO, with the
same `system_id`, `password` and `system_type`. Kannel's `transceiver-mode`.
| `receive_port` | `port` | The receiver bind's port, read only with `transceiver = false`.
Kannel's `receive-port`.
| `tls` | `false` | `true`: bind over TLS, both binds with `transceiver = false`. The SMSC's
certificate and host name are always verified, against the system CAs or `tls_ca_file`;
nothing turns verification off, so the bind password never goes to an unverified peer.
Kannel's `use-ssl`.
| `tls_ca_file` | unset | A PEM file of CA certificates used in place of the system CAs, for
an SMSC with a private CA or a self-signed certificate (put that certificate here). A
relative path is read from {product}'s working directory. Needs `tls = true`.
|===

== Kannel users

Each `[porth.kannel.users.<username>]` table is one caller of the Kannel `sendsms` API, named
by the table's key. See <<Authentication>>.

[cols="2,1,4",options="header"]
|===
| Key | Default | Meaning

| `password` | none | **Required.** The user's password.
| `allow_ip` | empty | The addresses and CIDR networks the user may call from, such as
`["127.0.0.1", "10.0.0.0/8"]`. Empty: any address.
|===

== HTTP users

Each `[porth.http.users.<name>]` table is one caller of the REST API. The name only tells the
tables apart: it is never sent or checked. See <<http-authentication>>.

[cols="2,1,4",options="header"]
|===
| Key | Default | Meaning

| `token` | none | **Required.** The caller's Bearer token: at least 16 characters, and
different from every other user's. Generate it, for example with `openssl rand -hex 32`.
| `allow_ip` | empty | The addresses and CIDR networks the user may call from, such as
`["127.0.0.1", "10.0.0.0/8"]`. Empty: any address.
|===

== Routing rules

Each message goes out through one SMSC, chosen once when it is submitted:

. the SMSC a Kannel client names with `smsc`, if any;
. else the SMSC of the longest prefix in `[porth.routing.prefixes]` that the destination
  number starts with;
. else `routing.default`;
. else nothing, and the submit is refused. See <<Routing>>.

With no `routing.default`, the prefix table is an allowlist: a number that no prefix matches
is refused. List only the country or network prefixes you send to. That also limits what a
leaked credential can cost in SMS pumping (fraudulent traffic to premium numbers):

[source,toml]
----
[porth.routing.prefixes]
"44" = "op-a"
"353" = "op-a"
----

* The allowlist covers the REST API and Kannel requests without `smsc`. A Kannel client
  that names an SMSC with `smsc` skips the prefix table (step 1), and can send to any number
  through that SMSC.
* On the Kannel API the check is per recipient. A recipient that no prefix matches is
  dropped, and the request still gets `202` if another recipient routes. Only when none
  routes is it refused with `403` (see <<Responses>>).

A prefix is digits only, and quoted, as a TOML key: `"4470" = "op-b"`. The number is matched
on its digits only: a `+`, dashes and spaces are dropped, so `+44-7012…`, `+447012…` and
`447012…` all match `"4470"`. `00` is not rewritten: `00447012…` matches only a rule that
starts with `00`.

== Example

A production file:

[source,toml]
----
[porth]
db = "postgresql+asyncpg://porth:secret@db.internal:5432/porth"
log_level = "INFO"
# log_format = "json"   # one JSON object per line

[porth.http]
host = "0.0.0.0"
port = 8080

[porth.http.users.app]
token = "3b1f0c9e5d7a4e2b8c6f1a0d9e7b5c3a"
allow_ip = ["10.0.0.0/8"]

[porth.kannel]
default_sender = "12345"

[porth.kannel.users.acme]
password = "secret-acme"
allow_ip = ["10.0.0.0/8"]

[porth.smsc.op-a]
host = "smsc.op-a.example"
port = 2775
system_id = "porth"
password = "secret"
throughput = 50

[porth.smsc.op-b]
host = "smsc.op-b.example"
system_id = "porth"
password = "secret-b"
throughput = 20

[porth.routing]
default = "op-a"

[porth.routing.prefixes]
"4470" = "op-b"
"4475" = "op-b"

[porth.delivery]
max_retries = 5
retry_delay = 10
worker_count = 10

[porth.mo]
url = "http://app.example/mo?from=%p&text=%a&charset=%C"
reply = true

[porth.store]
dlr_timeout_hours = 48
retention_days = 7
----

To migrate a database other than the one in `config/config.toml`, name the file:
`uv run alembic -x config=/etc/porth/config.toml upgrade head`.
