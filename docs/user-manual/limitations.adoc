= Limitations

{product}'s design commits to the following, but this release does not implement them yet.
The Planned column names the ticket for a planned change, or `—` where none is planned yet.

[cols="3,5,1",options="header"]
|===
| Area | Current behaviour | Planned

| Kannel-compatible `sendsms` API | `deferred` and `priority` are refused with Kannel's
`400` `… field misformed, rejected`, not honoured. A `udh` with GSM coding is measured against
160 characters, not the 140 octets less the UDH that one SMS holds, so a slightly long one may be
refused by the SMSC rather than by {product}. | —
| Security | {product}'s listeners speak plain HTTP: put a TLS proxy in front (see
<<tls-proxy>>). Without one, the Kannel API's credentials and the REST API's Bearer tokens
travel in clear. An `allow_ip` list is no substitute for a trusted network. The HTTP listener's `/health`, `/metrics`, `/status` and `/ready` endpoints
need no token: keep the HTTP listener on a trusted network. | —
| Metrics | Counters start from zero at every restart. A final status whose database
write rolls back is still counted. | —
| SMSC routing | Kannel's `unified-prefix` and per-SMSC `allowed-prefix`, `denied-prefix`
and `preferred-prefix` lists are not supported. Rewrite the rules as one prefix table (see
<<Routing rules>>). | —
| Restart window | A message the SMSC accepted just before a crash, before {product}
recorded it as `sent`, is sent again. So is one {product} could not record as `sent` because
the database was unavailable for its retries (about 7 s); its receipts are also ignored. A receipt that arrives before {product} has recorded
its message as `sent` (an early part of a long message, or a very fast SMSC) waits in memory,
up to about 15 s; one still waiting at a crash is lost, and that message stays `sent`. | —
| Scaling | One {product} per database; no standby that takes over without a restart, and
no horizontal scaling. | —
| SQLite | One writer at a time, so a lower throughput ceiling than PostgreSQL; no standby,
and the file on the local disk is the only copy (see <<Running on SQLite>>). A database that
a newer {product} has written is refused after a downgrade (`SQLite schema version N, this
porth expects M`). | —
|===
