= Limitations

{product}'s design commits to the following, but this release does not implement them yet.
The ticket reference identifies the planned change.

[cols="3,5,1",options="header"]
|===
| Area | Current behaviour | Planned

| Kannel-compatible `sendsms` API | Not served. No route reaches the handler. | POR-008, POR-005
| Message status polling | `GET /api/v1/sms/status/{id}` always answers `pending`. | POR-009
| Delivery receipts | Acknowledged and discarded. Status never becomes `delivered`, and no
Kannel `dlr-url` callback is made. | POR-002
| Receipt timeout | A message with no receipt never becomes `expired`. | POR-003
| Long messages | Rejected as `failed` instead of being sent as concatenated SMS. | POR-006
| Retries | A fixed delay with no backoff. Retries are processed one at a time. | POR-010
| Configuration | YAML values are not expanded from the environment, and the environment
cannot override a YAML file. `log_level` is ignored. | POR-012
|===
